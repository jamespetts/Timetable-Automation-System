Version 1.5

* The time-warp blackout now also switches off the street lights, and any other JMRI Lights listed in the street-light configuration, for the same period that the day/night lighting is blacked out. Lights return to their normal dusk/dawn state when the blackout ends.

* Fix the mobile app weather forecast showing an empty window for several seconds after opening. The window is now rendered before it is shown, so it opens fully populated instead of filling in only when the first refresh or memory change arrives.

* Added a loading indicator to the mobile app weather forecast, in the 2010s mobile app style, shown while the forecast data has not yet been published by the weather generator. It is removed as soon as the forecast arrives, and the caption changes to explain a stall if no data arrives within 12 seconds.

* The version number is now shown at the bottom right of the main menu, to the right of the GPL notice.

* The main menu buttons that open another window (Show timetable, Public information displays, Signallers' displays, Weather forecast, Setup and Help) are now toggles: choosing one a second time closes the window, or windows, that the first choice opened instead of opening a second copy.

* Setup dialogue opens faster: Workings, Timing points and Orientation tabs now load in the background with a horizontal progress bar shown until each tab is ready.

* Added optional occupancy sensor flicker monitor (BlockFlickerMonitor.py, off by default, enabled in Setup General tab). Shows one non-modal warning window with one message per Block.

* Added optional DCC power on at start-up (DccPowerOnStart.py, off by default, enabled in Setup General tab). Power already on is left unchanged; an unknown power state is never changed and is warned about in an orange-triangle warning window after a short wait. Also disables JMRI's built-in PowerOn.py Start-Up entry for the active profile so that power is turned on in one place only.

* Added optional DccPowerOffOnClose.py shutdown script (off by default, enabled in Setup General tab with "Turn DCC power off at close-down"). It turns the DCC track power off when JMRI closes, so the next start begins with a real power cycle. The Setup General tab enablement checkboxes now sit in two columns, with Enable time-based actions in the right-hand column, and the DCC power off option sits to the right of the DCC power on option.

* The DCC power on at start-up script is now kept first in the Start-Up list, before the panel file and the other start-up scripts, so track power is on before they act. The Setup window enforces this whenever it saves the Start-Up list.

* Fixed the DCC power off at close-down and fast clock save shutdown tasks returning a value from JMRI's void run method, which raised a TypeError at every shutdown.

* The time warp is now disabled for 30 seconds after the TimeWarpChecker start-up script begins. This stops input hardware that reports an input as active while it powers up from warping the clock during JMRI start-up. A time warp requested in that first 30 seconds is ignored; request it again after the 30 seconds.

* Added the Train detection tab to Setup, before Orientation. The roster is split into RailCom capable and not RailCom capable entries, detected from each entry's decoder definition rather than a fixed list. RailCom capable entries with RailCom switched off can be enabled through programming on main where the layout supports it. Entries detected as capable can be marked as not capable by hand for the benefit of later automatic working. The lower half lists the entries whose RailCom is switched on, with a tick box each for the RailCom initialisation fix and a function number that follows the selected entry.

* Fixed a data erasure bug in the orientation registers: a failed read of normalDirectionRegister.json or OrientationRegister.json wiped the in-memory data, and the shutdown save then wrote the empty state over the stored file. Failed reads now keep existing memory, an unreadable stored file is never overwritten at shutdown, and all three direction registers write atomically through temporary files.

* Fixed three start-up bugs: RailComFix used a function as a Runnable, the Workings setup tab referenced an undefined `baseDir` during the extra-script scan, and the orientation register save could escape an AccessDeniedException from the atomic move.

* The occupancy sensor flicker monitor and the DCC power on start-up script now share one warning window implementation (TASWarningWindow.py).

* The occupancy sensor flicker monitor now requires a double flicker (occupied-unoccupied-occupied or unoccupied-occupied-unoccupied within 3 seconds) before it reports, instead of a single occupied-unoccupied-occupied gap.

* The option to resume with the same fast clock time as the last shut down now also saves and restores the day of the week.
* Fix departure logging missing its WAITING to RUNNING move when Dispatcher allocates before the listener is attached (status fallback now always armed plus an immediate status check; first movement still wins when both paths fire; throttle address falls back to the working roster entry)
* Fix cancelled workings remaining on the small modern PID indefinitely; they now clear once booked departure time has passed
* Harden the orientation and last-reported-direction register saves: the file move is retried with a short delay when the stored file is briefly held open (as happens during the RailCom burst after a layout power cycle), and Java file errors are now caught so they can no longer escape onto the AWT event dispatch thread as uncaught exceptions. The atomic move is still attempted first on every attempt
